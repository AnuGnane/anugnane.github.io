Building with AI agents

The projects on this site are built with AI agents: scheduled cloud agents and Claude Code sessions, working through GitHub pull requests. Around them is ordinary engineering: small packages from a queue, one pull request each, and the repo's own gate and a review before anything merges.

The playbook, its log and the agents' prompts are in a private repo.

What it is

The loop first ran unattended over a holiday, 6 to 23 October 2026, while the owner was away with a phone and agents merged their own pull requests in seven repos. No person read those diffs before they merged.

How a piece of work moves

  • Queue files. Each repo had a HOLIDAY.md: its rules, then packages sized for one run, each traced to the repo's own backlog and naming its files and its gate. A decision only the owner could make became a ruling with a default.
  • Lanes. Each scheduled agent owned one section of one queue and one ID prefix, so two runs never took the same package; Shunt's repo had seven lanes. Planning lanes ran on Fable, coding lanes on Opus.
  • One package, one pull request. A run did the package on its own branch and pasted the gate's result into the pull request. A reviewer subagent read the whole diff for anything not asked for, any weakened test and any secret; the run fixed what it found and merged.
  • The Mac lane. What the cloud's Linux sandbox could not check (Swift app code, model changes needing local data, the risk map's pipeline) went up as needs-mac pull requests. When the laptop was idle, a script started a headless Claude Code session that gated them there, fixed what would not compile, and merged.

What kept it in bounds

  • Rule files. Each repo's CLAUDE.md or AGENTS.md still ruled, and each queue restated its hard rules: files never to open (environment, CSV and key files), paths never to edit (SQL, cron routes, data snapshots, the Xcode project), no new dependencies, never force-push.
  • Gates. Each repo's own: the full Xcode suite for Shunt, pytest and a slow golden test for gaffer, tests and a build for the web projects.
  • Caps. One unfinished branch and one open needs-mac pull request per lane; from 15 October, three packages a run.
  • What stayed with the owner. Signing, App Store Connect, devices, purchases and accounts were never queued. Actions that the tooling's permission checks refused stayed with the owner: installing the Mac lane's background job, and pushing the Wizard Shootout v1.0.0 release tag from the cloud. One run also refused a "go" for that release because another agent session, not the owner, had written it.

October in numbers

Counted on GitHub for 6 to 23 October 2026, London time: 1,049 pull requests merged across seven repos. Shiftie 259, gaffer 247, Shunt 169, Wizard Shootout 106, this site 95, the risk map 90 and Vouched 83 (the last two from 13 October). 69 were needs-mac pull requests.

The first week merged 143. On 13 October the schedule went from 17 cloud runs a day to 37, and from the 14th each day merged between 43 and 124. A count is not value: 176 of the 1,049 only refilled a queue, and by 20 October some lanes were merging empty refills.

What went wrong

  • A lane died, and nothing said so. On 16 October the platform disabled the routine for one of Shunt's lanes: its environment setting was one character short, almost certainly from a prompt update. Nothing alerted on it; it was found eight days later, while everything was being switched off.
  • The ramp outran the limits. Runs that took eight packages, read every notification and printed whole diffs used up the planning model's weekly allowance in under two days. A further ramp to 46 runs a day on 17 October was undone on the 20th, before the weekly limit hit.
  • The Mac under load. Seven Mac shifts hit the session limit before writing a handoff. Simulator processes kept the laptop's load in the hundreds for hours; one shift on 17 October merged nothing.
  • Permission checks traded for throughput. On 8 October the permission layer refused the Mac session's merges, and four gated pull requests waited for the owner's phone. From then on the Mac lane ran with Claude Code's permission checks skipped, guarded by the queue's rules, the gate, the reviewer and a time limit.
  • Agents reviewing agents. Every self-merged pull request was reviewed by a subagent. Shunt's tests passed, but in November the owner found it "buggy during gameplay with the piece drags and mechanics" and held its release. An independent review of the fix then caught a regression before merge: a pick during an animation could grab the wrong block.

How it runs now

On 24 October every routine was disabled and the Mac lane paused. Now one orchestrating session plans and reviews. It briefs separate agents, each in its own git worktree with one pull request per task, and reads every diff before anything merges.

  • Briefs carry each repo's hard rules and a required report: what changed, the gate's output, what was verified and what was not, and anything done beyond the brief. Agents do exceed briefs; each case is flagged to the owner before merge.
  • iOS repos merge after a green build and test gate on the Mac. A website merge is a deploy, so it waits for the owner's explicit yes each time.
  • Anything that leaves the machine or carries legal weight stays with the owner: signing, uploads, App Store submission and release, and declarations.

From the October run's playbook, log, agent prompts and Mac-lane scripts, the queue and rule files in each repo, and merged pull requests counted on GitHub on 19 November 2026.
